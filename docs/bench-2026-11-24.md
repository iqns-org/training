## What it proves

1. **Server-side persona works with zero client cooperation.** The
   re-baked chat template injects "You are Kandi..." whenever a request
   omits a system message: `Who are you?` -> *"I'm Kandi."* The earlier
   "I'm talking to SmolLM" mystery was the template's original default
   slot — not the weights, not the quant.
2. **The adapter's value is behavioral, not naming.** Both models now
   *say* Kandi (template); only kandi *is* in-voice: terse identity,
   correct prime answer, consistent 3am persona. The base rambles a
   "shapeshifter" fiction and gets a one-word arithmetic question wrong.
3. **`How are you feeling?` is the honest gap** — answered warmly, in
   voice, but never self-names. Next data round: in-context identity
   rows (persona inside assistant turns for feeling/mood prompts), not
   just the template slot.
4. **Emoji bleed**: kandi answered a JSON instruction with "🌦️". Keep a
   handful of format-fixture rows in the corpus so compliance survives
   a domain fine-tune.
5. **fp16 speed on Orin**: base ~88 tok/s, kandi ~54 tok/s (LoRA apply
   cost); both beat the int4 dequant path measured earlier — fp16 is
   confirmed the right dtype for this model size on this board.
